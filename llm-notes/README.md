## Decisions that changed the backlog

- Comin plus protected exact-commit release promotion replaces NATS/custom
  coordinators. Full CI and two runner backends are declared; live trust, cache
  coverage and acceptance are not assumed complete.
- Flux controllers exist but Git source/reconciliation is not wired. The registry,
  bootstrap, source and resource-ownership tasks are separate.
- Monitoring uses VictoriaMetrics/VictoriaLogs, not the old central Prometheus
  target tables. Existing log collection is retained; audit views are additional.
- Blocky bypass and registry-derived kresd local records are implemented/tested; remaining consumer adoption/recursion acceptance and
  phantasma removal remain open. Later notes explicitly closed slow boot as an
  accepted tradeoff; no new boot-performance issue is proposed.
- Current router6 already excludes PPPoE from its type enum, emits NIC rename
  rules and honors dhcp6.dnsAddress. Certificate expiry has a named flake check.
  Do not recreate those implementation findings. Rename behavior still needs
  runtime acceptance; CIDR math and cross-platform test exposure remain issues.
- Dual Lidarr instances already exist on bose/ravennue. Their deferred
  installation outline is retired rather than proposed as new work.
- The installation guide is rewritten against passage and extra-files staging
  in this pass, so the stale-documentation finding needs no future issue.
- Dev-machine refresh, current-directory inference, slot DHCP/DNS, KubeVirt
  isolation, non-root agent execution and scoped HTTPS/tea credentials already
  exist. Do not recreate stale setup/SSH-credential work from older reports.
- The Authelia incident note's guessed SQLite session deletion, storage-key wipe
  and immediate propagation/revocation claims are not retained as instructions.
  Version-tested revocation is a distinct issue. X5C re-enrollment does not revoke
  previously issued client certificates.
- Physical cutovers and unattended rollout require operator evidence/recovery.
  Historical LuCI bootstraps are retired; dated BT8 observations are preserved
  because manually managed devices are not reconstructible from Nix alone.
- Purchase prices, old upstream-bug status and broad product recommendations are
  retired rather than refreshed into new claims. Future work must verify pinned
  versions/hardware when it starts.

- OpenWISP image/configuration management and the Arteria NixOS gateway supersede the old BT8 gateway rotation and per-device in-flake UCI work. The [current issue index](../docs/work-tracking.md) preserves non-import tombstones and gated replacement work; historical source mappings below are provenance, not import instructions.

## Unselected ideas and accepted tradeoffs

No issue is proposed for optional blog/web ingress before content and ingress
requirements exist, multi-node/HA expansion, a new always-on web IDE, custom
DevPod provider extraction, or speculative service catalogs. Retrom embedded
Postgres/browser emulation/Steam bridges, arcade ingestion, PC-store wrappers,
Recyclarr, optional photo/book servers and Zigbee hardware are not selected work.
Resume only for a real use case, using current source/version evidence.

Do not reopen the rejected blanket connector lockout or durable OAuth-token
choice without operator steering. Serial root autologin is an explicit trusted
console tradeoff, now recorded in dev-machine docs. Root-key tightening and
certificate policy are deferred resilience decisions, not migration prerequisites.

The scratchpad's broad “one-shot agent permissions” and “CLI improvements” ideas
are not actionable stories yet. Authelia APP relocation conflicts with the later
foundational identity decision; Forgejo live-NFS relocation is superseded by the
local-service plus NAS pull-backup design. Multi-workspace extraction is deferred
until usage/capacity justify it. The concrete inventory, publication, lifecycle,
package-policy, pod isolation, dependency ownership and backup questions have
individual drafts. Resolved scratchpad items are not reopened.
